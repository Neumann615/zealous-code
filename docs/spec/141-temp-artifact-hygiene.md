# spec 141:工具副产物治理(临时文件卫生)

来源:dogfooding 140 问题分级 —— P2 #1 `__pycache__/` 测试副产物在 A1/A2/A3
三次进入"非预期修改"审计,触发"相同 P2 ×3 → 单独开 spec"规则(2026-10-20)。

## 问题

- 任务运行 `python -m unittest` 等测试命令(T2)后,`__pycache__/`、`*.pyc`
  等解释器副产物出现在工作区;zealous 的 auto-commit 只提交目标文件,副产物
  留在 untracked。
- 影响:
  1. dogfooding/审计的"非预期修改"噪音(3/9 任务出现);
  2. 与脏工作区守卫叠加时有阻碍风险:守卫把 untracked 视为脏(`??`),若
     任务先跑测试再写文件,写入会被 `Git 工作区有未提交改动` 拒绝,模型被迫
     走绕路(参见 B5 的行为观察)。

## 目标(不新增兜底逻辑的最小面)

1. 审计噪声:git 审计与 TUI 任务视图对解释器副产物(`__pycache__/`、
   `*.pyc`)降噪——归类"运行副产物"而非"非预期修改"。
2. 守卫语义:脏工作区守卫对纯副产物 diff 给出可解释的区分提示
   (仍拒绝写入,但错误信息区分"用户改动"与"运行副产物"),或允许
   明确忽略列表(默认关闭,配置开启)。
3. 不自动删除用户文件;不扩大 T1 写权限;保持 fail-closed。

## 非目标

- 不做全局 .gitignore 注入(仓库策略归用户)。
- 不缓存/清理测试产物(那是工具自身的事)。

## 验收

- 单测:副产物 diff 与真实用户改动的守卫错误信息可区分。
- dogfooding:含"先测后写"顺序的任务不再被副产物阻塞或污染审计。

## 优先级

P2(记录于 2026-10-20,扩展 dogfooding 阶段不开实现)。
